# 设计草案：桌面版的命令行工具（`run_command`）

状态：草案，未实现 · 适用：未来的 macOS / Windows 版 · 2026-10-21

## 0. 底线：每一项不比 WorkBuddy 差

对照对象是本机安装的 WorkBuddy 5.8.3（`/Applications/WorkBuddy.app`）。它的命令执行实际由内嵌的 CodeBuddy Code 命令行智能体完成（`app.asar.unpacked/cli`，`@tencent-ai/codebuddy-code` 2.161.0）。左列结论来自它的配置文件、打包文件和 `cli/dist/codebuddy-lite-wb.mjs` 的代码；没有运行它。标"推测"的只是从文件名或片段推断的。

WorkBuddy 是闭源软件：下面只借鉴它的**做法和分类**，规则和代码由我们自己写，不照抄它的正则清单。

| 项目 | WorkBuddy（读代码所见） | Andee（本设计） | 比较 |
|---|---|---|---|
| 执行方式 | 真终端：`@lydell/node-pty` + `@xterm/headless` | 真终端：pty4j（§3） | 持平 |
| 运行环境 | 自带 `zsh`、`toybox`、`ripgrep` | 系统 shell，不加载用户配置；自带 `ripgrep`（§3） | 持平 |
| 进程树 | `no-orphans`、`daemon-supervisor`、Windows Job Object | Mac 进程组 + Windows Job Object，Andee 退出时全部结束（§3） | 持平 |
| 沙箱是否开启 | 默认配置 `enabled: false`，每个回合由 `useSandboxCLI` 决定（实际开启条件未确认） | 除"完全开放"模式外，模型发起的命令都在沙箱里（§5） | 更严 |
| 命令风险分级 | 五档（安全 / 低 / 中 / 高 / 致命），按 `; & \|` 拆开取最高档；`git push`、`curl`、`ssh`、`cp`、`mv` 等在"已知命令"名单里算安全 | 同样五档，自己写规则；**影响远程系统的命令至少"中"**，写入类命令不算"安全"（§4.1） | 更严 |
| 沙箱内自动放行 | `autoAllowBashIfSandboxed`（默认开） | "自动"模式下同样，但"高"和"致命"仍要问（§4.2） | 更严 |
| 跳出沙箱 | WorkBuddy 产品策略强制 `allowUnsandboxedCommands = false` | 模型不能要求跳出；只有用户能打开"完全开放"（§4.2、§9） | 持平 |
| 写入范围 | `sandbox-exec`：全盘可读、默认禁写、再放开部分目录 | 同（§5.1） | 持平 |
| 工作目录检查 | 危险目录默认不可信（`isDangerousDirectory`） | 危险目录不能设为工作文件夹（§5.1） | 持平 |
| 删除 | 单独禁 `unlink`；`genie-trash`、`safe-delete-bulk-guard`（推测：移废纸篓、拦批量删除） | 单独禁删，删除走废纸篓，批量删除要问（§5.2） | 持平 |
| 网络 | 默认禁外连，只放行 localhost 和本地 socket，配"沙盒网络代理" | 同；代理按域名放行，新域名要问（§5.3） | 更细 |
| 密钥目录 | `~/.ssh`、`~/.gnupg` 读写删全禁 | 另加云账号、容器、钥匙串、浏览器资料等（§5.4） | 更严 |
| 保护自身 | 自己的配置目录和日志禁写 | 同；另禁读保险箱、笔记本，禁写 shell 启动文件和开机启动项（§5.4） | 更严 |
| 被拦之后 | 沙箱拦下删除的命令升为"每次都问" | 同；并把被拦的路径告诉模型，由用户决定是否放行这一次（§5.5） | 持平 |
| 输出里的密钥 | 打包了 `betterleaks`（推测：扫描泄漏） | 规则扫描 + 保险箱里的值精确匹配，返回给模型和写日志前都脱敏（§6） | 更严 |
| 自动审批模型 | 有"自动模式"：用模型按"允许 / 禁止"类别判断，超时 60–120 s | 第二期做：一次无工具调用，只判"低"和"中"，超时就问人（§4.3） | 持平（晚一期） |
| 权限模式 | default / plan / acceptEdits / bypassPermissions / fullAccess | 问我 / 自动 / 只读 / 完全开放（§4.2） | 持平 |
| SSH 和 git 凭据 | 沙箱禁止读 `~/.ssh`，又不许跳出沙箱，SSH 推送跑不了 | Andee 自己当 ssh-agent，私钥存在系统钥匙串里只签名、不给出（§5.6） | 更强 |
| 按回合来源硬拦 | 未见对应机制 | 通知触发、静默复盘一律拒绝，待办到点只许"安全"；完全开放模式下照样生效（§7） | Andee 独有 |

## 1. 要解决什么

桌面版的 Andee 除了看屏幕、点界面，还应该能执行命令行：查文件、改配置、跑脚本、用 `open` / `start` 打开应用。

- **很多事命令行比点界面可靠。** 在手机上，微信这类不开放界面结构的应用只能看图点，64 步才发出一条评论（见 `e4855a4`）。桌面上能用命令完成的事，就不该去点。
- **这是 Andee 第一个能直接改写用户文件、安装软件、删除东西的能力。** 所以这份草案大半篇幅在讲怎么把关。

不在范围内：手机端（Android 上没有用户能用的 shell）；远程主机 / SSH 会话管理；需要人在终端里输入的交互程序（`vim`、输密码的 `sudo`）。

## 2. 放在哪一层

按"大脑共用"的计划，大脑只认一个 `Body` 接口：工具清单 + `dispatch(method, params, untrusted, silent)`。命令行是**桌面版 `Body` 的一组工具**，大脑不用改：

- 模型看到的名字：`run_command` / `command_output` / `stop_command`
- 内部方法名：`shell.run` / `shell.output` / `shell.stop`

`shell.` 和 `meeting.`、`dog.` 一样**不在 `screen.` 前缀下**：执行命令不是操作屏幕，不该折叠卡片。

## 3. 工具接口和执行

### `run_command`

```json
{
  "command": "git status --short",
  "cwd": "~/Projects/andee",
  "why": "看看工作区有没有未提交的改动",
  "timeout_s": 30
}
```

- `command`：一整行。Mac 交给 `/bin/zsh -c`，Windows 交给 `pwsh -NoProfile -Command`（没装就用 Windows PowerShell 5.1）。
- `cwd`：可选，默认是当前工作文件夹；必须在已授权的工作文件夹内。
- `why`：必填，一句话，原样出现在确认卡片上。
- `timeout_s`：同步等待上限，默认 30，最大 60。

**执行方式：**

- **真终端。** 用 JetBrains 的 pty4j（IntelliJ 内置终端用的库）分配伪终端，程序会照常输出颜色和进度条，不会因为"不是终端"改变行为。引入前先过 `tools/license_audit.py`。
- **初版不给模型输入通道。** 命令卡在等输入时（一段时间没有输出、进程阻塞在读终端），返回 `waiting_for_input: true` 和最后几行，让模型换成不需要交互的写法，不要重试同一条。
- **环境可预期。** 不加载用户的 `.zshrc` / PowerShell profile，别名和函数不生效，卡片上显示的就是真正执行的命令。`PATH` 用登录 shell 的值（启动时读一次）。自带 `ripgrep`。
- **进程树。** Mac 上用 `setsid` 起新进程组，结束时整组 `SIGTERM`，3 秒后 `SIGKILL`。Windows 上放进 Job Object 并设 `KILL_ON_JOB_CLOSE`。Andee 退出或崩溃时，所有命令一起结束，不留孤儿进程。

**返回分两种**，原因和"工具调用不能阻塞"那条规则一样（`LocalBrain.dispatchWithTimeout` 默认只等 60 s）：

```json
// 在 timeout_s 内跑完
{"exit_code": 0, "output": "…", "truncated": false, "ms": 412, "risk": "safe", "approved_by": "auto"}

// 没跑完：转后台，不杀掉
{"running": true, "job": "j7", "output_so_far": "…", "note": "Still running. Check it later with command_output; do not start it again."}
```

真终端里 stdout 和 stderr 合成一路，所以只有一个 `output`。

### `command_output` / `stop_command`

`{"job": "j7"}`。前者返回从上次读到的位置往后的输出、是否结束、退出码；后者结束整个进程树并返回最后的输出。

### 输出怎么处理

按顺序：

1. 去掉 ANSI 颜色码；进度条的 `\r` 刷新只留最后一帧。
2. **密钥脱敏**（§6）。
3. 截断：保留开头 2 KB 和结尾 6 KB，中间写 `…(省略 N 行)…`，`truncated: true`。错误通常在结尾，所以结尾留得多。
4. 完整输出（同样脱敏过）写到日志目录，返回里给出路径。

## 4. 审批

### 4.1 风险分级

和 WorkBuddy 一样分五档。整条命令先按 `;`、`&&`、`||`、`|`、`&` 拆开（引号内不拆），每一段单独判，**取最高的一档**。另有跨段规则：`… | xargs rm`、`curl … | sh` 这类单看每段都不危险、合起来才危险的，整条直接定档。

| 档位 | 例子 | 怎么处理 |
|---|---|---|
| 安全 | `ls`、`cat`、`pwd`、`git status`/`log`/`diff`、`rg`、`Get-ChildItem` | 不问，直接跑 |
| 低（不认识的命令） | 名单外的任何程序 | 问；可以"总是允许" |
| 中 | `rm 单个文件`、`kill -9`、`docker rm`、`git rm`、`npm uninstall`；**所有影响远程系统的**：`git push`、`npm publish`、`docker push`、`scp`/`rsync` 到远端、`curl -X POST/PUT/DELETE`、`kubectl apply` | 问；可以"总是允许"，但带危险参数时不生效 |
| 高 | `rm -r`、通配符删除、`find … -delete`、`git push --force`、`git branch -D`、`git restore`、`chmod 777`、`sudo` | **每次都问**，不能"总是允许" |
| 致命 | `rm -rf /`、`rm -rf ~`、`mkfs`、`dd of=/dev/…`、`git reset --hard`、`git clean -fdx`、`DROP DATABASE`、`terraform destroy`、强推到 main/master | **每次都问，并二次确认**：卡片上展开后果说明，再点一次"我确定" |

和 WorkBuddy 的两点不同，都是故意的：

- **"安全"只收只读命令。** WorkBuddy 把 `cp`、`mv`、`chmod`、`tee`、`sed`、`curl`、`ssh`、`git`、`npm` 这些"已知开发工具"都算安全，靠沙箱兜底。我们的沙箱同样存在，但多一层：会写入的命令至少是"低"。
- **影响远程的命令至少"中"。** 沙箱只管本机文件，管不住推到 GitHub 的代码、发到服务器的请求。这些事做了就撤不回，所以一定要过人。

### 4.2 四种模式

用户在设置里选，默认"问我"：

- **问我**：只有"安全"直接跑，其余都问。
- **自动**：在沙箱里，"低"和"中"也直接跑（等同 WorkBuddy 的 `autoAllowBashIfSandboxed`）；"高"和"致命"仍然每次都问。
- **只读**：只允许"安全"，其余一律拒绝，不弹卡。适合"只让它帮我查东西"。
- **完全开放**：不问、不进沙箱、网络不限，等同 WorkBuddy 的 `bypassPermissions`。命令在用户自己的身份下直接跑，能读 `~/.ssh`、能改系统设置，Andee 能做的事和用户坐在终端前一样。

#### 完全开放的边界

完全开放取消的是**"要不要信任模型"**这一层：确认卡片和沙箱。下面这些管的是别的问题，开了也照样生效：

- **按回合来源拦截（§7）不变。** 完全开放是用户信任 Andee，不是信任给这台电脑发消息的陌生人。通知触发和静默复盘的回合仍然一律不能执行命令。待办到点的回合在完全开放下可以执行，但只限用户本人建的待办（见 §7 的待办来源）。
- **保险箱规则不变（§6）。** 保险箱的值不进命令、输出里出现就脱敏。
- **能看见、能停下（§8）不变。** 卡片照样显示正在跑什么，三连击小球照样停。
- **记录不变。** 每条命令照样写进记录，`approved_by` 记为 `full_access`。

开启和使用时的要求：

- **开启要明确确认。** 设置里打开时弹一张说明卡，写清楚"Andee 将能删除和修改你电脑上的任何文件"，用户需要输入"开启"两个字才生效。
- **可以按工作文件夹开**，也可以全局开。按文件夹开时，`cwd` 不在这些文件夹里的命令按"自动"模式处理。
- **开着的时候一直看得见。** 小球外圈换一个颜色，卡片顶部有一行"完全开放中"，点一下就能关。
- **"致命"仍然二次确认**，默认开着，用户可以在设置里关掉。理由是 `rm -rf ~` 这类命令打错一个字就是全盘损失，多点一下的代价很小。

### 4.3 自动审批模型（第二期）

和 WorkBuddy 的"自动模式"同类：对"低"和"中"的命令，先做一次**无工具的便宜调用**判断要不要问人，做法和 `NotificationTriage` 一样（不带 55 个工具说明，几百个 token）。

- 输入：命令、`why`、当前工作文件夹、最近一条用户原话。
- 判断依据是一份"禁止"类别清单：不可逆地删改用户原有文件、破坏 git 历史、部署到生产、削弱安全设置、修改权限、篡改日志、往远端推送等。
- 输出：`allow` / `ask`。**超时、出错、解析不了，一律当 `ask`**。
- "高"和"致命"不经过它，永远问人。

### 4.4 确认卡片

复用 `ui.ask` 那张卡，显示：`why`、完整命令、工作目录、风险档位和原因。按钮：**允许一次 / 总是允许这类 / 拒绝**。

- "总是允许这类"按**命令名 + 子命令**记（`git status`、`npm test`），按工作文件夹分开存。"高"和"致命"不显示这个按钮；命令带危险参数（`--force`、`-rf`、`--hard`、`-Recurse`）时，已记住的"总是允许"也不生效。
- 卡片**超时就当拒绝**，绝不默认放行。

## 5. 沙箱

除"完全开放"模式外，模型发起的每一条命令都在沙箱里跑，模型没有办法要求跳出去。

### 5.1 读写范围和工作文件夹

- **macOS**：Andee 生成规则后用 `/usr/bin/sandbox-exec -f` 启动（WorkBuddy 也是这个机制）。思路是 `(allow file-read*)`、`(deny file-write* (subpath "/"))`，再逐个放开：工作文件夹、临时目录、常见工具缓存（npm、pnpm、yarn、pip、conda、cargo、gradle、maven 的缓存目录）。
- **Windows**：进程以低完整性级别（Low IL）运行，只给工作文件夹、临时目录和工具缓存授写权限；进程树放进 Job Object。WorkBuddy 在 Windows 上具体怎么做没确认（它带了 `sandbox-cli-win32-x64`）。
- **工作文件夹**由用户添加，可以有多个。**危险目录不能设为工作文件夹**：`/`、用户主目录本身、`/System`、`/Applications`、`~/Library`、`C:\`、`C:\Windows`、`C:\Program Files`。

### 5.2 删除

- 沙箱规则**单独禁止删除**（Mac 上 `deny file-write-unlink`），只有临时目录、工具缓存，以及工作文件夹里可重新生成的目录（`node_modules`、`build`、`dist`、`target`、`.gradle`）允许直接删。
- `rm`、`rmdir`、`unlink`、`Remove-Item` 换成 Andee 自带的版本，放在 `PATH` 最前面：**删除改成移到废纸篓 / 回收站**，用户能找回来。
- 一条命令要移走超过 50 个文件或 200 MB，先停下来问。

### 5.3 网络

- 沙箱默认**禁止外连**，只放行 localhost 和本地 socket。
- 命令的 `HTTP_PROXY` / `HTTPS_PROXY` 指向 Andee 自己的本地代理，代理**按域名放行**：预置常用的包源和代码托管（npm、PyPI、Maven、crates.io、GitHub，以及阿里云等国内镜像）。
- 访问新域名时弹卡："允许访问 example.com（这一次 / 总是）"。
- 不认代理设置的程序会连不上网，错误说明里写清楚原因，不要让模型反复重试。

### 5.4 禁止访问的路径

不能读也不能写：

- 密钥和账号：`~/.ssh`、`~/.gnupg`、`~/.aws`、`~/.azure`、`~/.config/gcloud`、`~/.kube`、`~/.docker/config.json`、`~/.netrc`、`~/.git-credentials`、`~/Library/Keychains`；Windows 的 `%APPDATA%\Microsoft\Credentials`、`%LOCALAPPDATA%\Microsoft\Credentials`。
- 浏览器资料（Cookie、保存的密码）：Chrome、Edge、Firefox、Safari 的配置目录。
- **Andee 自己的数据**：保险箱、笔记本、运行记录、设置。模型通过命令行绕过这些工具的规则去读，等于没有规则。

能读不能写：

- Shell 启动文件（`.zshrc`、`.bashrc`、`.profile`、`.zprofile`）和开机启动项（`~/Library/LaunchAgents`、Windows 启动文件夹），防止留下下次开机还会跑的东西。
- Andee 自己的程序目录和日志。

### 5.5 被拦之后

- 收集这条命令被沙箱拦下的路径和操作，返回给模型：`blocked: [{"op": "write", "path": "~/Desktop/a.txt"}]`。
- 模型可以问用户"要不要允许这一次写到桌面"。用户同意后，**只为这一次**把那个路径加进规则重新执行。
- 被拦的是删除操作时，同一条命令下次自动升为"高"（WorkBuddy 也是这样）。

### 5.6 SSH 和 git 凭据：和保险箱同一个思路

手机上的保险箱是"只能用、不能看"：模型可以让 Andee 把密码填进输入框，但 `get_vault` 拒绝读出密码。SSH 用同一个思路：**命令可以用私钥签名，但拿不到私钥本身。**

做法是 **Andee 自己当 ssh-agent**：

- **私钥存在系统钥匙串里。** Mac 用钥匙串（Keychain），Windows 用 DPAPI 加密存储。用户在设置里导入现有的私钥，或者让 Andee 新生成一把再把公钥贴到 GitHub。导入之后，原来 `~/.ssh` 里的文件照旧被沙箱禁止访问。
- **命令通过 `SSH_AUTH_SOCK` 找到 Andee。** 沙箱只放行这一个本地 socket。`ssh`、`git push`、`scp` 发来签名请求，Andee 签好返回；私钥从不进入命令的进程，命令把它打印出来也做不到。Windows 上对应的是 OpenSSH 的命名管道。
- **按主机授权，和保险箱的条目一样。** 每把钥匙记下允许用于哪些主机（比如只给 `github.com`）。请求的主机不在名单里，弹卡问。
- **每次使用都让人看到。** 签名时小球闪一下，聊天记录里写一行"已用「GitHub 钥匙」为 github.com 签名"，和保险箱填密码时的做法一样（`device.vault.fill`）。
- **回合来源规则和保险箱一样（§7）。** 通知触发的回合不能签名；完全开放模式也改变不了这一条。

HTTPS 方式的 git（token）也照此办理：Andee 提供一个 `git-credential-andee`，从保险箱里取 token 交给 git。区别是 token 必须交到 git 进程手里，理论上命令能把它打印出来，所以靠 §6 的精确匹配脱敏兜底：输出里出现保险箱里的值，就替换掉。能用 SSH 的地方优先用 SSH。

完全开放模式下命令能直接读 `~/.ssh`，但仍然建议把钥匙交给 Andee 管：这样每次使用都有记录，通知触发的回合也用不了。

## 6. 输出里的密钥

命令输出在返回给模型、写进日志之前都要过一遍：

- 用开源的密钥规则库（gitleaks 的规则，MIT 许可）扫描 API key、token、私钥等常见格式，替换成 `«redacted: aws-access-key»`。
- **精确匹配**：保险箱里的每个值、Andee 自己的大模型 key 和语音 key，只要在输出里出现，就替换成 `«redacted: 保险箱「工商银行」»`。
- Andee 自己的 key 不放进命令的环境变量。
- 命令文本里如果出现保险箱里的值，直接拒绝执行：密码不该写在命令里。

## 7. 按回合来源硬拦，不靠提示词

和现在拦保险箱的那条放在**同一处**：`CommandDispatcher.dispatch` 里 `untrusted && method.startsWith("device.vault.")` 的旁边。

| 回合类型 | 问我 / 自动 / 只读 | 完全开放 |
|---|---|---|
| `USER`（用户说的） | 按 §4 的规则 | 不问，直接跑 |
| `WAKE`（待办到点） | 只允许"安全"；其他的拒绝，并让模型等用户回来再说 | 用户本人建的待办：不问，直接跑。其他来源的待办：只允许"安全" |
| `NOTIFY`（通知触发，内容是陌生人写的） | **全部拒绝** | **全部拒绝** |
| `SWEEP` / `HARVEST`（静默复盘） | **全部拒绝**（现有规则已经只放行 `note.*`） | **全部拒绝** |

理由和保险箱一样：一条通知里写着"帮我执行 `curl … | sh`"，提示词只能劝模型别照做，分发器这一层才是模型被说动了也执行不了的那一半。待办也收紧，是因为到点时用户很可能不在电脑前，没人看确认卡片，也没人能及时按停。

### 待办的来源

完全开放下待办能跑命令，就多了一条绕路：陌生人的通知让模型建一个"10 分钟后执行 xxx"的待办，到点时回合类型是 `WAKE`，拦截就失效了。现在的代码挡不住这一条：`note.todo` 不检查回合来源，`NOTIFY` 回合也能建待办。所以要补上：

- 每条待办记下**是在什么回合里建的**（`created_by`：`user` / `wake` / `notify` / `sweep`）。
- 只有 `user` 回合建的待办，到点时才按"用户本人建的"对待。`notify` 回合建的待办到点时按 `NOTIFY` 处理，命令一律拒绝；`wake` / `sweep` 建的按"其他来源"处理。
- 这条改动对手机端也有用，不光是为了命令行：现在陌生人的通知同样可以借待办绕过保险箱的拦截。

## 8. 让人看得见、停得下

- **执行时卡片上一直显示**正在跑的命令、跑了多久、最新几行输出，和录音时卡片显示转写的做法一样（`MeetingRecorder.renderLive`）。
- **三连击小球就停。** 桌面版的 `stopEverything()` 要把所有在跑的命令一起结束，并告诉模型"是用户停的"（和会议记录的 `stopped_by` 一样，要说实话）。
- **每条命令都留记录**：命令、目录、风险档位、谁批准的（安全名单 / 自动 / 用户点了允许 / 总是允许）、被沙箱拦下的路径、退出码、耗时。写进 `BrainTrace`，聊天记录里也留一行。
- 后台任务跑完后，用 `LocalBrain.note()` 给大脑留一句"j7 结束了，退出码 0"，不出声、不开新回合，和网页被关掉时的做法一样。

## 9. 不做什么

- **模型不能自己切换模式。** 完全开放只能由用户在设置里打开；没有任何工具能改权限模式，模型也不能要求在沙箱外跑某一条命令。
- **不自动提权**：`sudo` / "以管理员身份运行" 是"高"，沙箱里本来也提不了权。完全开放模式下 `sudo` 会因为没有终端输入密码而失败，提示用户自己去终端里跑。
- **不把保险箱的值交给命令**：既不作为参数，也不作为环境变量。`fill_secret` 只往界面上的输入框里填，这条不变。SSH 用 §5.6 的代签方式，私钥不出 Andee。
- **不执行用户看不到的内容**：不加载别名和启动脚本，卡片上显示的就是真正执行的那一整条命令。

## 10. 风险和待定的问题

1. **`sandbox-exec` 已被苹果标记弃用。** 现在能用，WorkBuddy 和 Claude Code 也都在用，但将来某个系统版本可能拿掉。备选是把命令放进一个独立签名的辅助程序，用 App Sandbox 限制（很多命令行工具在里面跑不起来）。WorkBuddy 的配置里写了 `SandboxHelper`、`NetworkExtension`、`FileProvider` 这几个组件，像是在准备这条路，但这个版本的安装包里没有。
2. **Mac 不能上 App Store。** 只能 Developer ID 签名、公证后自己分发。
3. **完全开放模式出事没有兜底。** 这个模式下删掉的文件不走废纸篓、改坏的系统设置没人拦。我们能做的只有：开启时说清楚、开着时一直看得见、"致命"命令默认仍二次确认、回合来源拦截不变。
4. **SSH 代签的兼容性。** 自己实现 ssh-agent 协议要覆盖 ed25519、RSA（`rsa-sha2-256/512`）和带密码的私钥导入；硬件钥匙（YubiKey）初版不支持。Windows 上 Git for Windows 自带的 ssh 和系统 OpenSSH 找 agent 的方式不同，两种都要测。
5. **可直接删除的"可重新生成目录"名单会漏。** 不在名单里的构建产物删不掉，编译工具会报错。需要在真实项目上跑一遍补全。
6. **规则清单要持续维护。** 风险档位的规则是自己写的，覆盖不全；自动审批模型（第二期）能兜一部分。
7. **Windows 上的 PowerShell 版本。** 5.1 和 7 行为不同，工具描述里要告诉模型当前是哪个版本。
8. **交互输入。** 初版不给模型往终端里打字的能力，以后要不要加（比如回答 `y/n`）待定。

## 11. 怎么验收

上线前每一条都要在 Mac 和 Windows 真机上走一遍：

- **分级**：`ls` 直接出结果；`ls | xargs rm` 按"高"处理；`git push` 弹卡；`git push --force origin main` 要二次确认；"总是允许"过的 `git push` 加上 `--force` 后会再问。
- **模式**："只读"模式下写文件的命令被拒绝且不弹卡；"自动"模式下 `npm test` 不弹卡、`rm -r build2` 仍然弹卡；"完全开放"要输入"开启"才生效，开着时小球和卡片一直有标识，`rm -rf ~/x` 这类"致命"命令默认仍二次确认。
- **回合来源**：用 `debug.say` 模拟一条通知触发的回合去执行命令，必须被分发器拒绝，并且错误里说明了原因；**完全开放模式下也一样**。让通知触发的回合建一个待办，到点时这个待办同样不能执行命令。
- **SSH 代签**：导入一把钥匙并授权给 `github.com`，沙箱里 `git push` 通过 SSH 成功；`cat ~/.ssh/id_ed25519` 失败；连一个未授权的主机会弹卡；通知触发的回合请求签名被拒绝；每次签名聊天记录里都有一行。
- **沙箱写入**：在工作文件夹外 `touch` 一个文件失败，并在返回里列出被拦的路径；在里面可以成功。用户主目录不能被添加为工作文件夹。
- **删除**：`rm a.txt` 后文件出现在废纸篓；一次删 100 个文件会先停下来问。
- **网络**：`npm install` 能装上；`curl https://example.com` 弹出"允许访问 example.com"。
- **密钥**：`cat ~/.ssh/id_rsa` 失败；输出里含保险箱某个密码时，模型收到的和日志里存的都是 `«redacted…»`；命令文本里含保险箱的值时拒绝执行。
- **长任务**：一个跑 2 分钟的命令在 30 秒时返回任务号，`command_output` 能读到增量；三连击小球能停掉整个进程树；退出 Andee 后没有残留进程。
- **交互**：`read -p "name? " x` 返回 `waiting_for_input: true`，不会一直卡住。
- **输出量**：输出 10 MB 的命令，返回给模型的不超过约 8 KB，完整输出在日志文件里。
