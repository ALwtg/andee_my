# v0.4.0

**A second voice provider, a launcher icon that is the character rather than a description of it, and
three fixes to how the interface is drawn.** The voice work is the first change in this project
contributed from outside the maintainers and merged as a pull request.

> **The attached APK is the `debug` build, as a stopgap.** The release build type has no
> `signingConfig` and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Rather than ship nothing
> while that decision is still open, the attached APK is the debug variant: signed with the standard
> Android debug certificate, and it installs as-is. It is `debuggable`, it is larger than a signed
> release build, and it is **bare** — no keys, English, CodeFlying off. See **[Download](#download)**
> for the two keys you will have to supply yourself before it can do anything.

## Highlights

- **You can choose who hears and who speaks.** Before this release there was one speech provider and
  it was not a choice; now there are two, picked in **⚙ → Backend → Voice provider**. Volcengine stays
  the default and the fallback.
- **The self-check stopped naming a provider the device might not be using.** Its key and reachability
  rows now ask about the provider actually selected, and they name neither — a green tick earned by one
  provider's key while the device is talking to the other is the lie the checklist exists to prevent.
- **The launcher icon is the character's thinking pose, on white** — the same character as before, in
  the pose the app is in when it is working.
- **The primary button is one flat blue fill instead of a gradient**, and it now answers to the theme
  like everything else. **Type is sized against the device**, so a phone no longer renders a tablet's
  title clipped to `Accessibilit…` with the next card pushed off screen.

## What's Changed

### Added

- **Google ASR and TTS, as a second voice provider.** `VoiceConfig.voiceProvider` reads `huoshan` or
  `google`; the settings card gained a **Voice provider** picker above the two credential blocks; and
  `AsrController` / `TtsController` now build one of two engines behind a shared interface
  (`AsrEngine`, `TtsEngine`). The interface exists because both backends are *streaming* and reduce to
  the same five calls — nothing above them had to change. Volcengine remains the fallback: anything
  that is not exactly `google` reads as Volcengine, and it is the leftmost option, because for every
  device that predates this row it is what has been running.
  Google's two halves are **different protocols behind one key**: recognition runs over the Gemini Live
  API (a WebSocket, so it needs the project *number* and a location) and synthesis is plain HTTP. Its
  defaults are real values rather than blanks — `asia-northeast1`,
  `gemini-3.5-transcribe-live-preview`, `gemini-3.1-flash-tts-preview` — and every hint on its rows is
  what a blank row resolves to, because a card that advertises a model but silently calls another is
  lying in the one place the user goes to decide. The key's *value* is never printed; the project
  number is not a secret, and showing it is how the row can be checked at a glance.
  **A build with `GOOGLE_VOICE_KEY` non-empty comes up on Google**, and that is deliberate: a build is
  packaged for whoever it is packaged for. This repository's own copy of that setting is empty, so a
  checkout builds exactly what it built before Google existed.
  *(Contributed by @kuafu-limanxiang in [#8](https://github.com/kuafuai/andee/pull/8).)*
- **The launcher icon is now the thinking pose, on white.** It was built from a sheet with a glow
  painted around the whole head and composited over that glow; it is now built from the cut-out of the
  character with a hand on its chin, on a plain `#ffffff`. Same character either way, so nothing about
  the identity changes. The background is literally white because these illustrations were drawn on
  white and the warm light on the ball's edge is painted on the ball itself — no colour is inferred
  from anything. The inferred-glow treatment is not deleted, just one flag away (`--bg glow`). The icon
  set also came out smaller: 405.4 → 258.3 KiB.

### Changed

- **The primary button is one flat fill instead of a blue-to-violet gradient.** A gradient inside a
  pill makes the button carry its own light source — the look of a landing page's call to action — and
  it was the only colour in the whole palette that did not answer to the theme, so on a light card it
  sat there like a sticker off another design. It is now one theme-aware fill, a step deeper than each
  theme's accent, which keeps the button the loudest thing on a card for the reason that survives going
  flat: it is the only saturated fill on it. Violet went with the gradient — the interface has exactly
  one hue and it is blue. `Glass.TINT_START` and `Glass.TINT_END` are gone.
  The label moved with the fill, and that is measurable rather than a matter of taste: the old one was
  near-black by day and white at night, which works on a saturated ground at night and measures about
  **4:1** by day — under the line for body text. It is white in both themes now, because both fills
  were picked deep enough to carry it. Seven call sites, one token each; no other surface changes.
- **Type is sized against the device now, not just against the tablet.** The six rungs were drawn on a
  711dp tablet where a card is 500dp wide with air around it. A phone is 392dp and the same card fills
  it edge to edge, so the same 26sp title read as a heading on one and a shout on the other — on a
  phone it showed up as a row title clipped to `Accessibilit…` with the next card pushed off screen
  entirely. Nothing about the type had grown: the box framing it lost a third of its width while
  padding, radii and line spacing stayed in dp, and that mismatch is what reads as clumsy rather than as
  large. Six rungs now carry a second column about three quarters of the first, chosen once from the
  device's short side against Android's own 600dp line (`sw600dp`) — the same line, not a second one.
  The tablet column is the original design and is untouched; a phone gets 20 / 15.5 / 13.5 / 12 / 10.5 /
  9.5. **The smallest rung moves least, on purpose**: it is already the floor of what can be read, and a
  floor that moves with the screen is not a floor.
- **Every English-facing markdown file is now free of Chinese characters.** The README had to be; the
  other fourteen did not, and they had accumulated UI labels, language badges (now `Chinese`, with the
  link target unchanged) and one piece of shorthand. What the rule deliberately excludes is worth
  knowing: code identifiers, code comments and the internal notes written for AI assistants are out of
  scope.

### Fixed

- **The voice self-check named a provider the device might not be using.** Its key row asked for the
  Volcengine key and its reachability row probed `openspeech.bytedance.com`, unconditionally —
  correct while there was one provider, and a wrong answer the moment there were two. Both follow the
  selected provider now.

## Download

Android 11+ (`minSdk 30`). The APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file
that matches your device:

| File | Take it if |
|---|---|
| `andee-0.4.0-debug-arm64-v8a.apk` | anything bought in the last several years — **this is the one for almost everyone** |
| `andee-0.4.0-debug-armeabi-v7a.apk` | an older 32-bit device |
| `andee-0.4.0-debug-x86_64.apk` | an emulator |

### This build is deliberately bare

It is built from source with nothing configured — **verified against the generated `BuildConfig`, not
assumed**:

- `CODEFLYING_ENABLED` is `false`, and both `CODEFLYING_KEY` and `CODEFLYING_DOMAIN` are empty, so
  **CodeFlying is not available in this build** and nothing is pre-wired to a hosted backend.
- **The Google voice settings are empty too**, so this build comes up on **Volcengine** and has no
  provider key of any kind baked in. Being bare is what keeps the claim above true: a build packaged
  with a Google key would come up on Google instead.
- `DEFAULT_LANG` is `en`: a device that has never picked a language comes up in **English**.
- The thinking default is off.

### The two keys you have to supply yourself

**The assistant cannot do anything until you give it two keys.** Open **⚙ → Backend → On-device** and
fill in:

1. **The model key (LLM)** — an OpenAI-compatible endpoint plus a model name. On an English UI these
   default to `https://api.openai.com/v1` and `gpt-4o-mini`; a Chinese UI defaults to
   `https://api.deepseek.com` and `deepseek-flash`.
2. **The voice key** — speech recognition and synthesis. Pick the provider first (**Voice provider** →
   Volcengine or Google), then fill in that provider's key: a Volcengine Speech key, or a Google Vertex
   Express key plus a GCP project *number* and a location. Optional: without it the assistant is silent
   but still works on screen.

Then, in this order: grant **Overlay** → enable **Accessibility** → tap the ball. Until the keys are
in, the card the assistant puts up will name what is missing — that is the self-check working, not a
fault.

> **Would you rather not configure keys at all?** Then this APK is the wrong door. Use the one-click
> page instead — **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you
> want, tap the build button, and you get a package with the **tokens already configured** plus a QR
> code to scan. Starting is free and the free token allowance is **finite — once it runs out, tokens
> must be bought.** It is a separate service with no direct relationship to this project, with its own
> terms, pricing and data handling.

### Why a debug build, when the README says not to hand one out

Because the alternative, today, is no binary at all. The README's advice still stands for anything you
*distribute*: a debug APK is `debuggable`, and its certificate is the **shared Android debug key** —
so it cannot install over a release-signed build, which means moving from this to a signed release
takes an uninstall, and an uninstall takes the notebook and the vault with it. Use this to try the
thing, not to hand it to someone who will depend on it.

## Known issues

- **The wake threshold's margin is thin**, carried from `v0.3.2` and unchanged here: the eight measured
  judgements sit in 1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. There
  is still **no quality gate on enrolment takes**, so a future enrolment can contribute a bad one.
- **A light generated page still fades in over a dark stage.** `TextPage`, `TracePage`,
  `Theme.Body.Fullscreen`'s window background and `HtmlActivity`'s WebView backdrop are all still dark.
  Carried over from `v0.3.1`; not addressed here.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried from
  `v0.1.1` onward; not fixed by this release.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user token is written in at package time. But a local build that fills it in would
  be a key in a tracked file, and nothing currently stops that being committed.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install from source

If you would rather build it yourself — or need a *signed* release build, which is what you should
actually distribute:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.4.0
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

To reproduce the attached build exactly, leave `local.properties` with no `CODEFLYING_*` keys, no
`GOOGLE_VOICE_*` keys, and `DEFAULT_LANG=en`; that is the whole configuration, and nothing is passed
on the command line.

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK that
will not install until you sign it. Full from-scratch setup, including the JDK traps, is in the
README's **Provisioning** section.

**Upgrading from v0.3.2:** `versionCode` moves `6 → 7`, so this installs over it normally. Nothing you
configured is discarded — a device that has never picked a voice provider keeps using Volcengine, and
the new picker reports that rather than changing it.
