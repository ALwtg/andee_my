# v0.4.1

**Pages became versions, the brain learned to see its own work, and the default look is now the light
one.** Three fixes ride along: the settings card no longer throws the conversation away, every face
got its finishing touches, and a page can be revised without growing a second page beside it.

> **The attached APK is the `debug` build, as a stopgap.** The release build type has no
> `signingConfig` and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Rather than ship nothing
> while that decision is still open, the attached APK is the debug variant: signed with the standard
> Android debug certificate, and it installs as-is. It is `debuggable`, it is larger than a signed
> release build, and it is **bare** — no keys, English, CodeFlying off. See **[Download](#download)**
> for the two keys you will have to supply yourself before it can do anything.

## Highlights

- **A revision is a new version of a page, not a second page.** Ask for a change and the panel keeps
  one row for it with the old revisions behind it — **Versions** opens the list, and any of them can
  be made current again, as a new version rather than by rewriting history.
- **The brain can see the pages it made.** `list_pages` and `get_page` are two new read-only tools,
  and the newest few also ride along on every turn — so "change the table from yesterday" reads
  yesterday's table back instead of producing a lookalike or denying it exists.
- **A fresh install comes up light.** A device that has chosen a theme keeps it; the dark palette is
  one tap away in **Settings → Appearance**.
- **Changing the model no longer wipes the conversation.** Flipping the thinking switch used to reset
  the history mid-task, and the model would then say it had no record of a page it had just built.

## What's Changed

### Added

- **Page revisions, kept as versions.** `ChatHistory.Entry` gained a `groupId` (which artifact it
  belongs to) and a `version` (which revision — **only ever increasing**). The **Made for you** panel
  collapses to one row per artifact with its version number (`v3`); older revisions stay on disk, and
  **Go back to this** makes an old one current **as a new version**, so the history stays append-only
  and a rollback can itself be rolled back. One artifact keeps at most 20 revisions.
  **Which artifact a revision belongs to is decided on the device, never asked of the model** — reading
  a page back arms the target, the panel's revise button hands it over, and `show_html` gained an
  optional `revise` for naming one explicitly. The target is **consumed rather than merely read**:
  found by hand on a device, where a target left standing folded a second, unrelated page in as a
  later version of the first.
- **`list_pages` and `get_page`.** A page drawn yesterday existed for the user (it is on the shelf)
  and not for the model that drew it, so a request to revise earlier work could come back as a fresh
  table that merely resembled the old one, or as a flat "I have not made that". `list_pages` returns
  every page with its id, title, date, size and whether the file is still there; `get_page` reads one
  back by id, **any revision of it**. Both are deliberately outside the `screen.` prefix, so neither
  folds the card nor stops at the lock screen — reading a file reaches neither. Alongside them the
  newest few ride on the per-turn user message as a short index, the same place and for the same
  reason as the notebook index: a tool only answers a question the model thought to ask.

### Changed

- **The default appearance is light, not dark.** A fresh install now comes up on the light palette.
  A device that has touched the setting keeps whatever it chose — the rule reads only an explicit
  `night`, so nothing here can overrule a user who picked dark. Written against the *non-default*
  value on purpose: it makes changing the default later a one-line edit rather than a migration, and
  the dark palette stays one tap away in **Settings → Appearance**.
  **Dark is not the older palette and nothing about it is being corrected** — it is the look this app
  was designed on, and light was derived from it as the inversion. The frame drawn before the saved
  setting is read moves with the default, so a fresh device does not flip palettes one frame in.
- **Every face got its props, its idle life and its finishing touches.** Andee's mouth dropped twice
  (`−0.185 → −0.235 → −0.285`) so there is a finger of sphere between its eyes and its smile instead
  of the two crowding together. **Sleep stopped being a flattening pose**: the squash that melted the
  resting and sleeping ball into a puddle is gone, and the floppy horns, the ⌣ eyes and (while
  sleeping) the bubble carry it instead.

### Fixed

- **Changing the model, the thinking switch or the reasoning effort no longer wipes the
  conversation.** Closing the settings card rebuilt the local brain on any config difference, and a
  rebuild is the loss of the whole conversation — flipping the thinking switch reset the history
  mid-task, and the model then said it had no record of a page it had just built. Only a change of
  **who answers** (mode, key, endpoint) rebuilds now; model, thinking and reasoning effort are request
  parameters and are retuned in place, taking effect on the next request.

## Download

Android 11+ (`minSdk 30`). The APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file
that matches your device:

| File | Take it if |
|---|---|
| `andee-0.4.1-debug-arm64-v8a.apk` | anything bought in the last several years — **this is the one for almost everyone** |
| `andee-0.4.1-debug-armeabi-v7a.apk` | an older 32-bit device |
| `andee-0.4.1-debug-x86_64.apk` | an emulator |

### This build is deliberately bare

It is built from source with nothing configured — **verified against the generated `BuildConfig`, not
assumed**:

- `CODEFLYING_ENABLED` is `false`, and both `CODEFLYING_KEY` and `CODEFLYING_DOMAIN` are empty, so
  **CodeFlying is not available in this build** and nothing is pre-wired to a hosted backend.
- **The Google voice settings are empty too**, so this build comes up on **Volcengine** and has no
  provider key of any kind baked in.
- `DEFAULT_LANG` is `en`: a device that has never picked a language comes up in **English**.
- The thinking default is off.

### The two keys you have to supply yourself

**The assistant cannot do anything until you give it two keys.** Open **⚙ → Backend → On-device** and
fill in:

1. **The model key (LLM)** — an OpenAI-compatible endpoint plus a model name. On an English UI these
   default to `https://api.openai.com/v1` and `gpt-4o-mini`; a Chinese UI defaults to
   `https://api.deepseek.com` and `deepseek-flash`.
2. **The voice key** — speech recognition and synthesis. Pick the provider first (**Voice provider** →
   Volcengine or Google), then fill in that provider's key: a Volcengine Speech key, or a Google Vertex
   Express key plus a GCP project *number* and a location. Optional: without it the assistant is silent
   but still works on screen.

Then, in this order: grant **Overlay** → enable **Accessibility** → tap the ball. Until the keys are
in, the card the assistant puts up will name what is missing — that is the self-check working, not a
fault.

> **Would you rather not configure keys at all?** Then this APK is the wrong door. Use the one-click

### Why a debug build, when the README says not to hand one out

Because the alternative, today, is no binary at all. The README's advice still stands for anything you
*distribute*: a debug APK is `debuggable`, and its certificate is the **shared Android debug key** —
so it cannot install over a release-signed build, which means moving from this to a signed release
takes an uninstall, and an uninstall takes the notebook and the vault with it. Use this to try the
thing, not to hand it to someone who will depend on it.

## Known issues

- **Twenty revisions is a per-artifact cap, and a global one sits behind it.** `MAX_VERSIONS` (20)
  trims the oldest revisions of one artifact; the older `MAX_PAGES` (100) still governs how many
  page-bearing entries exist at all — and since a revision is an entry, that global number now counts
  versions rather than pages. Neither is surfaced anywhere in the UI.
- **The wake threshold's margin is thin**, carried from `v0.3.2` and unchanged here: the eight measured
  judgements sit in 1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. There
  is still no quality gate on enrolment takes.
- **A light generated page still fades in over a dark stage.** `TextPage`, `TracePage`,
  `Theme.Body.Fullscreen`'s window background and `HtmlActivity`'s WebView backdrop are all still dark.
  Carried over from `v0.3.1`; **worth reading again in this release**, because the app's own default is
  now light while those four surfaces are not.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried from
  `v0.1.1` onward; not fixed by this release.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user token is written in at package time. But a local build that fills it in would
  be a key in a tracked file, and nothing currently stops that being committed.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install from source

If you would rather build it yourself — or need a *signed* release build, which is what you should
actually distribute:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.4.1
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

To reproduce the attached build exactly, leave `local.properties` with no `CODEFLYING_*` keys, no
`GOOGLE_VOICE_*` keys, and `DEFAULT_LANG=en`; that is the whole configuration, and nothing is passed
on the command line.

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK that
will not install until you sign it. Full from-scratch setup, including the JDK traps, is in the
README's **Provisioning** section.

**Upgrading from v0.4.0:** `versionCode` moves `7 → 8`, so this installs over it normally. Nothing you
configured is discarded: a device that picked a theme keeps it (only a device that never picked one
changes, and it moves to light), and pages that already exist on the shelf keep their own row — an
artifact that predates this release reads as a single version until you revise it.
