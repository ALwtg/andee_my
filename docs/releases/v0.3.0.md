# v0.3.0

**The assistant stops living inside the accessibility service.** Everything else in this release is
smaller than that one change, and it is the reason this is a minor bump rather than a patch: a ROM
that revokes accessibility now costs one capability instead of the whole app.

> **No APK is attached to this release, on purpose.** The release build type has no `signingConfig`
> and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Shipping a binary a
> reader cannot install would be worse than shipping none. Build it yourself — see *Install* below.

## Highlights

- **Losing accessibility no longer loses the assistant.** The body — ball, card, microphone, ASR/TTS,
  brain socket, scrollback, todos — used to be built inside an `AccessibilityService`. A ROM that
  revoked accessibility (HyperOS, observed) took all of it: no ball, no way to talk, no way back
  except knowing which switch to find. The body is now a foreground service, and the accessibility
  service is a shim that hands the screen capability over and takes it back.
- **The screen can still be read when accessibility is gone.** `MediaProjection` is the platform's
  other way in — one consent dialog, asked from the notification and only when Andee is blind.
  Deliberately weaker: `screen.screenshot` only, no aim grid, no element list, no tapping.
- **The self-check page stays up until you close it.** It used to hand the screen to the assistant on
  the first return from a Settings screen, taking the list away after row one. A row you just fixed
  also stops showing as red.
- **Every mood has a pose now** — a wink, eyes that look up and aside, two puffy hands and pop-in
  props — and five gesture moods can be asked for by name.
- **The default look is the blue horned Andee**, with the launcher icon, README covers, social
  previews and org avatar regenerated from the same source art.
- **Closing a page always puts the assistant back at full size**, whatever shape the card was in
  before.

## What's Changed

### Added

- **The body is a foreground service (`BodyCoreService`); the accessibility service is a shim**
  (`ScreenBodyService`). `screen.*` now goes through a provider, so a call with no accessibility
  throws a readable error instead of holding a controller built around a dead binding. The launch is
  a **persistent notification** that carries whether screen control is up and the way back to
  Settings — posted by the body, so it survives the state it describes. `-PdbgSuffix=` builds a
  parallel package for device verification, so a test build no longer requires uninstalling (which
  would throw away chat history, notebook and vault).
- **`MediaProjection` screen reading.** One consent dialog from the notification's second action, and
  only while it is the only option; `ACTION_ACCESSIBILITY_SETTINGS` stays the first action, because
  the projection buys reading, not acting.
- **Ball expressions**: a `Pose` layer on top of each `Face` — wink, looking up and aside, lowered
  lids, a squashed resting body, two hands (open, fist, pointing) and pop-in props. Five gesture
  moods (wink, wave, protect, celebrate, rest) can be requested by name or synonym in the model's own
  text; the prompt says to keep them rare. Only a look with `BallLook.gestures` reads it, so the
  older characters are unchanged.
- **The blue horned Andee is the default look**, first in `BallLooks.ALL`, so a fresh install and a
  factory reset both land on it. Its numbers were measured off the reference picture through the
  renderer's own camera rather than eyeballed.
- **The CodeFlying per-user token is read from `assets/andee_key.txt`**, with `BuildConfig` as the
  fallback for dev builds, so the base APK is identical across users and the Gradle build cache no
  longer misses per user.
- Debug builds gain `BallLabActivity` for mood screenshots.

### Changed

- **The version check moved to `https://api.heyandee.com`** from `https://andee.kuafuai.net`. The old
  host was on the mainland, where an unfiled domain is answered with a 403 block page that arrives in
  the app as 查不到. The address is still a hardcoded constant and still the only one the user did not
  configure. A fresh DNS record is not everywhere at once, so on the wrong resolver that row reads
  查不到 until it propagates — intended, not a fault to report.
- **Closing a page puts the assistant back at full size, unconditionally.** The fold that makes room
  for a page is ours, so undoing it is ours too, and it was missing from the model's route.
- Both READMEs point their CodeFlying links at the `/andee` one-click landing page.

### Fixed

- **`ui.show_html` no longer needs accessibility.** `awaitUncovered()` asked its question through
  `requireScreen()`, so with accessibility off the one tool that draws a page answered "accessibility
  is off" and the assistant told the user it could not show them anything. Introduced by the split,
  which rewrote every call site mechanically; this one was on a shared path and should not have
  thrown.
- **The self-check no longer mistakes a re-creation for a launch.** This page sends the user out
  through its own rows, so the platform killing it while they are away is routine: returning used to
  unfold the card and finish before a single row was drawn. `savedInstanceState != null` tells the
  two apart.
- **The body stays off the screen while the check page is up.** The page was still the resumed
  Activity with the assistant's fullscreen card painted over it — and that window is fullscreen even
  when the ball is compact, so it swallowed touches and 完成 did nothing.
- **A just-fixed row stops showing as red on resume.** Returning from a Settings screen used to
  compare languages and nothing else, so a row the user had just fixed stayed red until they found
  重新检查.
- **A perch slide dragged the whole card off-screen**, half untouchable, and a voice failure on a
  device with no voice set up repeated forever. Both fixed.
- **`screen.screenshot`'s schema claimed an aim grid and an element list**, both exactly untrue on
  the projection path — which is the only screen tool that still works there.
- **Three documents still described the pre-split architecture.** Both READMEs said "this app *is*
  the accessibility service" and pointed at the wrong file to read first; the permission table said
  of accessibility that "every screen action errors", which stopped being true when the
  `MediaProjection` fallback landed. The look and mood counts in both READMEs were also stale (five
  looks and fourteen moods, against six and nineteen in the code).

### Removed

- `tools/check_launcher_icon.py`, `tools/cosmic_backdrop.py` and the old `make_launcher_icon.py`,
  replaced by a generator built on `tools/andee_head.py`. All three were written for the previous
  character and a star-field backdrop, neither of which is in use any more.

## Known issues

- **The foreground-service start path and the microphone promotion were not verified on a device.**
  The split was verified by assembling and by 37 unit tests; the two things that need a real ROM are
  the foreground-service start and claiming the microphone type from the launcher.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried over
  from `v0.1.1` and `v0.2.0`; not fixed by this release.
- **`settleRecheck`'s retry is reasoned from the code path, not measured.** Writing the notification
  listener into `enabled_notification_listeners` does not stick, so the "granted but not bound" state
  cannot be manufactured from adb.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user `kft_` token is written in at package time. But a local build that fills it
  in would be a key in a tracked file, and nothing currently stops that being committed.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install

Android 11+ (`minSdk 30`), arm64-v8a for anything bought in the last several years. There is no binary
in this release; build one:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.3.0
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK. Either
way the APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file that matches the device.
Full from-scratch setup is in the README's **Provisioning** section. Then, in this order: grant
Overlay → enable Accessibility → tap the ball → put in your own keys under ⚙.

**Upgrading from v0.2.0:** `versionCode` moves `3 → 4`, so this installs over it normally. You will
now see a **persistent notification** — that is the body, and it is what keeps the assistant alive
when accessibility is taken away. The accessibility service keeps the same class name, so an existing
grant survives the upgrade. Four foreground-service permissions are added to the manifest; they are
install-time, with no dialog, and they exist so the body can run and so the screen can be read
without accessibility.
