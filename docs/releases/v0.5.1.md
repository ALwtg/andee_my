# v0.5.1

**Two ways the assistant could quietly stop working, both fixed.** Its nightly review died with the
process and never came back; and on a Xiaomi-family device, the power policy was reaping it in the
background with nothing anywhere telling the user why. Neither is a new capability — they restore two
things that were already supposed to happen.

> **The attached APK is the `debug` build, as a stopgap.** The release build type has no
> `signingConfig` and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Rather than ship nothing
> while that decision is still open, the attached APK is the debug variant: signed with the standard
> Android debug certificate, and it installs as-is. It is `debuggable`, it is larger than a signed
> release build, and it is **bare** — no keys, English, CodeFlying off. See **[Download](#download)**
> for the two keys you will have to supply yourself before it can do anything.

## Highlights

- **The nightly review survives being killed, and comes back after a reboot.** The alarm outlived the
  process but there was often nothing left to run it, and a reboot never re-armed it. Worse, the review
  reads the conversation from memory — which dies with the process — so even a recovered sweep found
  nothing to review and did nothing. Both halves are fixed: the review can now tell *"already done"*
  from *"died before it could"*, and it can rebuild the dialogue it missed from the scrollback on disk.
- **On Xiaomi, Redmi and POCO there is now a row for auto-start, which is what actually keeps it
  alive.** MIUI reaps background processes on a timer and, without that grant, the process cannot bring
  itself back — the symptom is *"it closes by itself after a while"*. The self-check now reads that
  switch and offers a one-tap door to the MIUI screen that holds it. On any other device the row is
  absent, because there it would be a control that does nothing.

## What's Changed

### Fixed

- **The quiet-hour review survives the process being killed, and is re-armed after a reboot.** The
  sweep is an `AlarmManager` alarm, so it outlives the process — but when it landed there was often no
  service left to run it, and after a reboot it was not re-armed at all. And the review reads the
  conversation from memory, which dies with the process, so a recovered sweep found **"0 messages to
  review"** and did nothing. Two halves close it: the notebook now records when the sweep last actually
  ran — the one fact that separates *"already reviewed"* from *"died before it could"* — and the
  dialogue can be rebuilt from the persisted scrollback (user and assistant rows, each re-stamped with
  its own clock) when the in-memory history is empty. On start the service catches up: it waits out a
  quiet window that has not finished, skips a stretch already swept, and otherwise runs the review it
  missed. Measured on a device: a sweep after a restart listed the four prior turns and completed.
- **A Xiaomi-family device has a self-check row for auto-start.** MIUI's power policy reaps background
  processes on a timer (measured at one kill every 40–60 minutes on the maintainer's tablet), and
  without the auto-start grant `START_STICKY` cannot bring the process back — the symptom a user
  reports is *"it closes by itself after a while"*, with nothing saying why. The new row reads the
  vendor AppOps op (`OP_AUTO_START = 10008`, by reflection — it has a number but no name this app can
  spell) and offers a one-tap door to MIUI's auto-start manager, probing the known components in order
  because MIUI has renamed that activity across versions. It is **`WARN`, not `FAIL`**: with auto-start
  off the app is fully alive right now, and it is the *future* that degrades. The row **only exists on
  Xiaomi, Redmi and POCO** — matched on brand words, since the MIUI build property would need a hidden
  API and the words are free.

### Changed

- **The version number is a deliberate departure from this project's own policy.** Both commits in this
  release are `feat`, and the policy says MINOR for a new capability — which would have made this
  `0.6.0`. It is `0.5.1` because neither adds a capability: they restore two things that were already
  supposed to happen, and what a user gets by upgrading is the existing features surviving a night
  rather than a new one arriving. Nothing in the wire contract or an existing configuration breaks
  either way. The departure is recorded in the CHANGELOG entry as well, rather than left for a reader
  to notice.
- **`CLAUDE.md`'s self-check section no longer claims a count.** It said "Seven things in the design
  are load-bearing" and had listed fifteen for some releases. The sentence now says "a number of",
  which is the same reasoning the versioning policy records — a count written into prose goes stale.

## Download

Android 11+ (`minSdk 30`). The APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file
that matches your device:

| File | Take it if |
|---|---|
| `andee-0.5.1-debug-arm64-v8a.apk` | anything bought in the last several years — **this is the one for almost everyone** |
| `andee-0.5.1-debug-armeabi-v7a.apk` | an older 32-bit device |
| `andee-0.5.1-debug-x86_64.apk` | an emulator |

### This build is deliberately bare

It is built from source with nothing configured — **verified against the generated `BuildConfig`, not
assumed**:

- `CODEFLYING_ENABLED` is `false`, and both `CODEFLYING_KEY` and `CODEFLYING_DOMAIN` are empty, so
  **CodeFlying is not available in this build** and nothing is pre-wired to a hosted backend.
- **The Google voice settings are empty too**, so this build comes up on **Volcengine** and has no
  provider key of any kind baked in.
- `DEFAULT_LANG` is `en`: a device that has never picked a language comes up in **English**.
- The thinking default is off.

### The two keys you have to supply yourself

**The assistant cannot do anything until you give it two keys.** Open **⚙ → Backend → On-device** and
fill in:

1. **The model key (LLM)** — an OpenAI-compatible endpoint plus a model name. On an English UI these
   default to `https://api.openai.com/v1` and `gpt-4o-mini`; a Chinese UI defaults to
   `https://api.deepseek.com` and `deepseek-flash`.
2. **The voice key** — speech recognition and synthesis. Pick the provider first (**Voice provider** →
   Volcengine or Google), then fill in that provider's key: a Volcengine Speech key, or a Google Vertex
   Express key plus a GCP project *number* and a location. Optional: without it the assistant is silent
   but still works on screen.

Then, in this order: grant **Overlay** → enable **Accessibility** → tap the ball. Until the keys are
in, the card the assistant puts up will name what is missing — that is the self-check working, not a
fault.

> **Would you rather not configure keys at all?** Then this APK is the wrong door. Use the one-click
> page instead — **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you
> want, tap the build button, and you get a package with the **tokens already configured** plus a QR

> terms, pricing and data handling.

### Why a debug build, when the README says not to hand one out

Because the alternative, today, is no binary at all. The README's advice still stands for anything you
*distribute*: a debug APK is `debuggable`, and its certificate is the **shared Android debug key** —
so it cannot install over a release-signed build, which means moving from this to a signed release
takes an uninstall, and an uninstall takes the notebook and the vault with it. Use this to try the
thing, not to hand it to someone who will depend on it.

## Known issues

- **Auto-start is only checked on Xiaomi, Redmi and POCO.** Other vendors have the same kind of policy
  under different names (Huawei and HONOR were both encountered during development), and there is no
  row for them yet.
- **The auto-start row reads a vendor op by reflection.** If a future MIUI version moves or renames it,
  the read fails closed — it answers "not allowed" rather than crashing — but that also means a device
  where auto-start *is* on could be told it is off. The row is `WARN`, so nothing breaks; it would just
  be wrong.
- **The recovered review reviews the scrollback, not the original turn boundaries.** A sweep that runs
  after a restart sees the conversation rebuilt from persisted rows, which is enough to review but is
  not the same object the live conversation was.
- **The wake threshold's margin is thin**, carried from `v0.3.2` and unchanged here: the eight measured
  judgements sit in 1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. There
  is still no quality gate on enrolment takes.
- **A light generated page still fades in over a dark stage.** `TextPage`, `TracePage`,
  `Theme.Body.Fullscreen`'s window background and `HtmlActivity`'s WebView backdrop are all still dark.
  Carried over from `v0.3.1`; the app's own default has been light since `v0.4.1`.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried from
  `v0.1.1` onward; not fixed by this release.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user token is written in at package time. But a local build that fills it in would
  be a key in a tracked file, and nothing currently stops that being committed.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install from source

If you would rather build it yourself — or need a *signed* release build, which is what you should
actually distribute:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.5.1
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

To reproduce the attached build exactly, leave `local.properties` with no `CODEFLYING_*` keys, no
`GOOGLE_VOICE_*` keys, and `DEFAULT_LANG=en`; that is the whole configuration, and nothing is passed
on the command line.

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK that
will not install until you sign it. Full from-scratch setup, including the JDK traps, is in the
README's **Provisioning** section.

**Upgrading from v0.5.0:** `versionCode` moves `9 → 10`, so this installs over it normally. Nothing you
configured is discarded, and nothing already on the device is re-processed — the notebook's
`last_sweep_at` starts empty, which reads as "nothing has been swept yet", so the first catch-up after
this build runs once and settles.
