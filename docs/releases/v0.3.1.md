# v0.3.1

**A patch release by decision, against the project's own definition.** The delta carries six `feat`
commits and [CHANGELOG.md](../../CHANGELOG.md#versioning-policy) says a new capability is MINOR, so
the policy would have made this `0.4.0`. It is recorded rather than left for someone to reconstruct
from the history, because a version number that disagrees with its own policy is the kind of thing
that reads as an oversight later.

> **No APK is attached to this release, on purpose.** The release build type has no `signingConfig`
> and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Shipping a binary a
> reader cannot install would be worse than shipping none. Build it yourself — see *Install* below.

## Highlights

- **The card has a day palette now**, alongside the night one it always had. What blocked it was that
  `Glass`'s colours were `const val`s — inlined at compile time, unable to vary at runtime at all.
  They are getters over a day and a night `Palette`, every name unchanged, which is what let forty
  call sites stay where they are. The backdrop is one photograph with two veils, so there is no asset
  change.
- **A "Looks & expressions" card in Settings**, showing every look and every expression on a ball of
  its own. Look chips save on tap; expression chips only preview.
- **The local LLM endpoint and model follow the UI language.** An English card advertises *and calls*
  `https://api.openai.com/v1` + `gpt-4o-mini`; a Chinese card stays on `https://api.deepseek.com` +
  `deepseek-flash`. Hint and fallback come from one resolver, so the box cannot advertise one endpoint
  and silently call another.
- **A generated page picks its own look.** The prescribed HOUSE STYLE block is gone from the
  `show_html` description. Expect a wider spread of looks.
- **`POST_NOTIFICATIONS` is actually requested now.** It had been declared in the manifest since the
  beginning and mentioned by no Kotlin file, so on Android 13+ everything the app posted was dropped
  in silence — including the persistent notification that is the way back to it.
- **Tapping the fix button in the check card no longer throws the list away.** The trip to Settings is handed to
  the page, which is in the task the destination lands in and gets a resume callback on the way back.

## What's Changed

### Added

- **A day and a night palette** (`ui/Theme.kt`). Night is the default and the values the app already
  shipped with; day is the inversion, with three values deliberately left alone because they name a
  position rather than a colour — the well stays recessed, the thumb stays raised, and the sheen flips
  end for end. A theme is a process-global with one listener, shaped after `AppLocale`, because almost
  no UI here lives in an Activity and no system mechanism could reach a Service's overlays. The
  backdrop is blurred once and veiled in whichever direction the palette needs — black down to 0.22 at
  night (the original composite to the digit), **white** up to 0.62 by day.
- **A "Looks & expressions" card in Settings** (`ui/ExpressionsUi.kt`).
- **The local LLM endpoint and model follow `uiLanguage`**, from one pair of resolvers. CodeFlying is
  deliberately *not* switched by language: its model belongs to the hosted backend, and an English
  build inventing `gpt-4o-mini` at that endpoint would name a model CodeFlying does not serve.
- **Errand trips from the check card are handed to `SelfCheckActivity.showForErrand`** rather than made
  by the card. `Fix.Grant` goes through the same door, so Allow on the microphone and notification rows stops ending on the
  launcher as well.
- **Every look gets the prop-and-pose layer**, not just Andee — stars, a heart, a shield, a sweat bead,
  the sliced lid, and an idle life that lets a look wear its own expressions and nap while nothing is
  happening. A look that is not alive standing next to one that is reads as the broken one.
- **Andee's horns stand higher and hang on two springs**, so a wiggle or a turn swings them; the mood
  sets where they rest. It wears a short run of safe faces while idle and naps for under a minute
  instead of sleeping until touched. Hands are a round palm, a thumb and two capsule fingers, and the
  wink carries a floating heart instead of a hand — a V, a pointing finger and a thumbs-up were each
  tried and each misread at this size.

### Changed

- **Both READMEs lead with what it is**, and the "why it is not the assistant already in your phone"
  section moved above the examples. Two earlier drafts were self-defeating and both were caught by
  reading them: one claimed "not a tool, not a companion" and then proved it with a capability list,
  the other denied being an assistant that operates your phone while the whole section below was
  exactly that. The negations are now scoped to a category and the section opens with the axis that
  separates the two.
- **The English README no longer contains a single Chinese character** — `\p{Han}` returns nothing. The
  language badge, five look names, a dozen Chinese-language links and the language markers on the
  CodeFlying sites were all changed. The Chinese README keeps its own language.

### Fixed

- **`POST_NOTIFICATIONS` was declared and never requested.** On Android 13+ that silently dropped every
  notification this app posts: the persistent notification that is the route back to screen control,
  and every reminder `Scheduler` fires. The codebase half knew — `Scheduler` carries a comment blaming
  this permission for its own failure to notify, and nothing tested the claim. The row that looked like
  it covered this (the notification-access row) is the notification *listener*, which can be granted and green while
  every notification the app sends disappears. Two things were needed beyond a catalog entry: on API 32
  and below the permission does not exist and `checkSelfPermission` answers **denied** for anything it
  does not know, so the entry is skipped rather than answered; and it is named in `SOLO_IDS`, because
  that set is a whitelist whose default would have handed it to `ask_user`.
- **The check card's fix button no longer ends on the desktop.** The card was closed and the assistant folded
  before the destination launched, so a window — which gets no `onResume` — lost the list, and the
  destination went out with `FLAG_ACTIVITY_NEW_TASK` into a task of its own, leaving nowhere of ours to
  return to. Verified on the tablet (Mi Pad 5, `.dbg` package).
- **Four documents corrected.** The data-flow table in both `DISCLAIMER`s and both `permissions`
  documents named `api.deepseek.com` as the default destination for the conversation with no mention of
  the language dependency added in this release — so an English reader was told their data goes
  somewhere it does not. `CLAUDE.md` still called the `show_html` house style "the one deliberate
  exception" to the single-palette rule, two paragraphs after the same file recorded that the house
  style had been removed. And the `POST_NOTIFICATIONS` row said only that a reminder would not arrive,
  which undersold it.

### Removed

- **The raised mitts.** Andee's expressions were built around a pair of mitts raised at the side — a
  fist under the chin, two fists up for celebrating, a hand on the belly for resting — and every one
  read as a lump at the eighty dp the ball is actually drawn at, with the parts sharing the body's own
  colour and material. The ball keeps the paws it hangs off the screen edge with. No expression
  collapses into CALM for it: a mood is read through its own `Face` row and its body motion, neither of
  which ever came from the pose table.
- **The `show_html` house style**, and the `LocalPrompt` §7 sentence that pointed at it and then
  asserted "that style is what you look like".

## Known issues

- **A light generated page fades in over a dark stage.** `TextPage`, `TracePage`, `Theme.Body.Fullscreen`'s
  window background and `HtmlActivity`'s WebView backdrop are all still dark, so the page's own palette
  and the surface it arrives on do not agree. The flash is **not verified on a device** — what was run
  is `:app:compileDebugKotlin`.
- **The READMEs enumerate five looks under a "six looks" heading.** Six is right (`andee`, `bajie`,
  `cream`, `imp`, `rabbit`, `bear`); the five named are the ones other than the default. Which five to
  name is the maintainer's call rather than a fact to be guessed at, so it was left.
- **The microphone promotion has still not been on a device.** The body's foreground-service start path
  was exercised in this release (the errand verification above required a running assistant), but
  `promoteForMicrophone` specifically was not.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried from
  `v0.1.1`, `v0.2.0` and `v0.3.0`; not fixed by this release.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user `kft_` token is written in at package time. But a local build that fills it in
  would be a key in a tracked file, and nothing currently stops that being committed.
- **`settleRecheck`'s retry is reasoned from the code path, not measured.** Writing the notification
  listener into `enabled_notification_listeners` does not stick, so the "granted but not bound" state
  cannot be manufactured from adb.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install

Android 11+ (`minSdk 30`), arm64-v8a for anything bought in the last several years. There is no binary
in this release; build one:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.3.1
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK. Either
way the APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file that matches the device.
Full from-scratch setup is in the README's **Provisioning** section. Then, in this order: grant
Overlay → enable Accessibility → tap the ball → put in your own keys under ⚙.

**Upgrading from v0.3.0:** `versionCode` moves `4 → 5`, so this installs over it normally. With the
**local brain** (the out-of-box default), if your UI is in English and you never saved an LLM endpoint
or model, this release **re-points them to OpenAI** — `https://api.openai.com/v1` and `gpt-4o-mini`.
That is the one behaviour change here that can move your data somewhere new; a saved value is never
touched, and CodeFlying is deliberately not switched by language.
