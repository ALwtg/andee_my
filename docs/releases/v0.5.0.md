# v0.5.0

**A conversation that has finished is now put away rather than carried forever, and it can be read
back when you ask about a detail.** That is the new capability this release is numbered for. Two
smaller changes ride along: a choice card's question and answer now land in the scrollback, and the
README explains what signing actually protects.

> **The attached APK is the `debug` build, as a stopgap.** The release build type has no
> `signingConfig` and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Rather than ship nothing
> while that decision is still open, the attached APK is the debug variant: signed with the standard
> Android debug certificate, and it installs as-is. It is `debuggable`, it is larger than a signed
> release build, and it is **bare** — no keys, English, CodeFlying off. See **[Download](#download)**
> for the two keys you will have to supply yourself before it can do anything.

## Highlights

- **Finished topics get put away, not deleted.** A stretch of conversation that has ended was the most
  expensive thing in every later request and the least likely to be needed again. It is now folded into
  a titled summary with a one-line marker left in its place, and the verbatim conversation is archived
  beside it. In the scrollback those messages become a card offering **Continue**, **Transcript** and
  **Made here** — so you can pick the thread back up, read what was actually said, or reopen what was
  produced in it.
- **It reads a detail back instead of guessing.** Ask about something a summary left out and it opens
  the archived conversation rather than answering from the one-liner or telling you it never happened.
- **A choice card's question and answer stay in the conversation.** The card used to come and go, so
  the scrollback showed the assistant acting on a choice nobody could see being made.
- **The README says what signing is protecting** — and the tool count in it is no longer a number that
  can go stale.

## What's Changed

### Added

- **Topics: a finished stretch of conversation is folded away, and can be picked back up.** The nightly
  review marks where topics begin and end among the user's numbered turns (`fold_topic`), the device
  validates the range and swaps it for a one-line marker **after the turn it names**, and the verbatim
  conversation is archived so it can be read back.
  Three tools, all `localOnly`: **`fold_topic`** — **review-only**, and an ordinary turn that calls it
  is refused, because folding is irreversible from the model's side and a request is not the moment to
  spend it; **`list_topics`** — each folded topic's id, title, when it ended and how many messages it
  covers; and **`get_topic`** — the whole back-and-forth as plain text, cut past a limit with
  `truncated` saying so.
  The device refuses a fold **with a reason** rather than a retry: a turn number not in the list, a
  range ending at the latest turn (nothing has started after it, so nothing says it ended), something
  inside still waiting on an answer, an overlap with a topic already put away, too short, or a scene
  active. At most **three topics per review**, and they are put away when the review ends rather than
  when the tool is called. The summary's fourth line is deliberately **what the model left out**,
  because a summary that reads complete is one whose details are lost.
  In the scrollback the folded topic is a card standing where its messages stood. **Continue** inlines
  the archived conversation into the next turn; **Transcript** opens the full record, and says so
  honestly when the text has been cleared and only the summary is left; **Made here** reopens the pages
  produced inside that topic, each with its version.
- **`debug.sweep`, for testing the review on demand.** Loopback only — it needs `adb forward` to reach,
  and says so rather than vanishing.

### Fixed

- **A choice card's question and answer now land in the scrollback.** `ui.ask` spoke the question and
  handed the chosen option straight to the brain, so the card came and went and the conversation showed
  the brain acting on a choice nobody could see being made. The question is an assistant row now and
  the answer — the button, or the words said instead — is a row of your own. A timeout writes nothing,
  because nothing was chosen.

### Changed

- **The README says what signing is for.** The signature is the only thing stopping a fake "update" from
  installing over a user's copy and inheriting the accessibility service, the secure-settings grant and
  everything in the vault. That is now stated where signing is already discussed, along with why a
  per-machine debug key is what produces `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.
- **The tool count in the READMEs and the DISCLAIMER is no longer a number.** Both said "sixty-odd
  tools", which was accurate when written and had drifted as tools were added. The sentences now
  describe what the tools do and say "a few dozen" — a count written into prose is a count that goes
  stale, which is a lesson this project's own versioning policy had already learned once.
- **Dark is still one tap away, and this release changes nothing about it.** Noted here only because
  the previous release changed the default; nothing about appearance moved in this one.

## Download

Android 11+ (`minSdk 30`). The APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file
that matches your device:

| File | Take it if |
|---|---|
| `andee-0.5.0-debug-arm64-v8a.apk` | anything bought in the last several years — **this is the one for almost everyone** |
| `andee-0.5.0-debug-armeabi-v7a.apk` | an older 32-bit device |
| `andee-0.5.0-debug-x86_64.apk` | an emulator |

### This build is deliberately bare

It is built from source with nothing configured — **verified against the generated `BuildConfig`, not
assumed**:

- `CODEFLYING_ENABLED` is `false`, and both `CODEFLYING_KEY` and `CODEFLYING_DOMAIN` are empty, so
  **CodeFlying is not available in this build** and nothing is pre-wired to a hosted backend.
- **The Google voice settings are empty too**, so this build comes up on **Volcengine** and has no
  provider key of any kind baked in.
- `DEFAULT_LANG` is `en`: a device that has never picked a language comes up in **English**.
- The thinking default is off.

### The two keys you have to supply yourself

**The assistant cannot do anything until you give it two keys.** Open **⚙ → Backend → On-device** and
fill in:

1. **The model key (LLM)** — an OpenAI-compatible endpoint plus a model name. On an English UI these
   default to `https://api.openai.com/v1` and `gpt-4o-mini`; a Chinese UI defaults to
   `https://api.deepseek.com` and `deepseek-flash`.
2. **The voice key** — speech recognition and synthesis. Pick the provider first (**Voice provider** →
   Volcengine or Google), then fill in that provider's key: a Volcengine Speech key, or a Google Vertex
   Express key plus a GCP project *number* and a location. Optional: without it the assistant is silent
   but still works on screen.

Then, in this order: grant **Overlay** → enable **Accessibility** → tap the ball. Until the keys are
in, the card the assistant puts up will name what is missing — that is the self-check working, not a
fault.

> **Would you rather not configure keys at all?** Then this APK is the wrong door. Use the one-click
> page instead — **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you
> want, tap the build button, and you get a package with the **tokens already configured** plus a QR
> code to scan. Starting is free and the free token allowance is **finite — once it runs out, tokens
> must be bought.** It is a separate service with no direct relationship to this project, with its own
> terms, pricing and data handling.

### Why a debug build, when the README says not to hand one out

Because the alternative, today, is no binary at all. The README's advice still stands for anything you
*distribute*: a debug APK is `debuggable`, and its certificate is the **shared Android debug key** —
so it cannot install over a release-signed build, which means moving from this to a signed release
takes an uninstall, and an uninstall takes the notebook and the vault with it. Use this to try the
thing, not to hand it to someone who will depend on it.

## Known issues

- **Folding is only ever done by the nightly review.** There is no way for you to fold a topic by hand,
  and a very long conversation therefore keeps costing context until the review next runs. `debug.sweep`
  can trigger it, but it needs a cable.
- **A folded topic's transcript can be cleared with nothing but the summary left** — the card says so
  rather than opening an empty page, but the conversation is gone at that point.
- **The wake threshold's margin is thin**, carried from `v0.3.2` and unchanged here: the eight measured
  judgements sit in 1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. There
  is still no quality gate on enrolment takes.
- **A light generated page still fades in over a dark stage.** `TextPage`, `TracePage`,
  `Theme.Body.Fullscreen`'s window background and `HtmlActivity`'s WebView backdrop are all still dark.
  Carried over from `v0.3.1`; the app's own default has been light since `v0.4.1`, so the contrast
  between the two is more visible than it was.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried from
  `v0.1.1` onward; not fixed by this release.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user token is written in at package time. But a local build that fills it in would
  be a key in a tracked file, and nothing currently stops that being committed.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install from source

If you would rather build it yourself — or need a *signed* release build, which is what you should
actually distribute:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.5.0
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

To reproduce the attached build exactly, leave `local.properties` with no `CODEFLYING_*` keys, no
`GOOGLE_VOICE_*` keys, and `DEFAULT_LANG=en`; that is the whole configuration, and nothing is passed
on the command line.

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK that
will not install until you sign it. Full from-scratch setup, including the JDK traps, is in the
README's **Provisioning** section.

**Upgrading from v0.4.1:** `versionCode` moves `8 → 9`, so this installs over it normally. Nothing you
configured is discarded, and nothing already on the device is folded — topics begin with the first
review after this build is installed, so a conversation from before it is simply never put away.
