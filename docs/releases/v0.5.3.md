# v0.5.3

**You can now tell it to stop, out loud, and it will.** Say "Exit Andee" or "Take a break" and the
assistant cancels what it is doing and closes — microphone and wake word included — with no model call
in the path. The rest of the delta is aiming: a large fix for apps that hand accessibility a blank root,
found by measuring rather than by reading code.

> **The attached APK is the `debug` build, as a stopgap.** The release build type has no
> `signingConfig` and there is no keystore in this repository, so `assembleRelease` emits
> `app-<abi>-release-unsigned.apk`, which will not install until you sign it. Rather than ship nothing
> while that decision is still open, the attached APK is the debug variant: signed with the standard
> Android debug certificate, and it installs as-is. It is `debuggable`, it is larger than a signed
> release build, and it is **bare** — no keys, English, CodeFlying off. See **[Download](#download)**
> for the two keys you will have to supply yourself before it can do anything.

**This release carries a teammate's work.** The voice-exit feature arrived as
**[PR #14](https://github.com/kuafuai/andee/pull/14)** from
[@lirongkuafuai](https://github.com/lirongkuafuai), closing
**[issue #13](https://github.com/kuafuai/andee/issues/13)** — fifteen commits, reviewed and merged. The
aiming fix is from the maintainer.

## Highlights

- **A way out that does not need the model.** "Exit Andee" / "Take a break" (and the Chinese
  equivalents) is matched **on the device** and handled before any card answer or brain submission, so
  it works even when the model is unreachable. It cancels the running task, stops the service and
  closes the assistant, which also stops the microphone and the wake word.
- **It is a whole-utterance match, on purpose.** *"How do I exit Andee"*, *"cancel my subscription"*
  and a quoted command all stay ordinary turns. A phrase arriving on an automatic follow-up window is
  ignored. While a meeting is recording it refuses, and says why.
- **Aiming on an app that hides its element tree is now much better.** On WeChat the grid label was
  sitting **on top of** a button and hiding it; gestures on such an app must now be aimed off a fresh
  zoom (measured: zoom-aimed taps changed the screen **33/41** times, screenshot-aimed **124/211**, and
  the misses opened profiles, followed people and deleted comments); and the model is told when a menu
  is open instead of guessing and reopening it.

## What's Changed

### Added

- **Voice exit** (`asr/VoiceExitCommand.kt`). Recognition happens on the device with no model call —
  the utterance is matched before any card answer or brain submission. It cancels the running task,
  stops the body service, and closes the assistant; **the microphone and the wake word stop with it**,
  and the app icon starts it again. The trigger list is deliberately tight and matched whole-utterance:
  asking how to exit, cancelling a subscription, or quoting a command must remain an ordinary turn
  rather than unexpectedly shutting the assistant down. A phrase arriving on an **automatic follow-up
  window is ignored** (`userInitiated`), with its own test. **While a meeting is recording it refuses**
  and explains that the meeting must be ended and its minutes saved first. Teardown is guarded so that
  a late transcript, a wake callback or a TTS fallback cannot reopen an overlay after exit was asked
  for — the failure that would make "it closed" untrue a second later.
- **`popup_open` / `popups` on tap, long-press and screenshot results.** Read from the window list,
  which survives an app withholding its tree. The model could not tell an open menu from a closed one
  by eye and reopened one **six times**; a blind tap aimed *inside* a popup is now refused, with the
  reason, instead of landing on whatever the popup is covering.

### Fixed

- **Aiming on an app that withholds its element tree** (measured on WeChat 8.0.79 / HONOR, where
  accessibility gets a blank root and every tap is aimed by eye off a screenshot downscaled to ~0.48×).
  The injection itself was already exact — **every miss was an aiming miss**:
  - **The grid labels moved to the edges.** Printed at each cell's centre, the `H` column's label sat
    exactly on WeChat's 「··」 button and **hid it**. They are rulers now — letters along the top edge,
    numbers down the left — and nothing printed inside a cell belongs to the device.
  - **A gesture on a tree-blind app must fall inside a zoom taken since the last one.** Zoom-aimed taps
    changed the screen **33/41** times; screenshot-aimed ones **124/211**, and the misses opened
    profiles, followed people and deleted comments. This is the general form of the rule that already
    guarded the tap after blind typing.
  - **A cell is now fifteen parts, not nine** (`3 × 5`: `top-left` … `bottom-right`). The old nine
    names still parse as **aliases** mapped to the outer rows, so anything written against the previous
    vocabulary aims where it used to — that was deliberate.
  - **The markers are magenta (`#E000FF`), not red.** Red is every unread badge in every Chinese app,
    and a red crosshair next to WeChat's red dot read as part of the app rather than as the device's
    own annotation. The caption also moved **above** the ring, because below is where the next target
    is.
  - **Prompt side:** close a small menu by tapping its **opener** again rather than with `back` (the
    menu is unfocused, so `back` left Moments entirely), and keep list progress instead of restarting
    from item 1.

### Changed

- **The READMEs' description of aiming was corrected.** Both said it taps by *"which third of it"* and
  that the crosshair is **red** — neither survived this release. They now say "which part of it" and
  magenta.
- **The English README's language badge is back to ASCII.** A web edit on 2026-10-21 changed the badge
  label from `Chinese` to the Chinese characters for it, putting Han characters back into a file that
  is checked for zero of them. The link target never moved.

## Download

Android 11+ (`minSdk 30`). The APK is **per-ABI** (`splits` in `app/build.gradle`), so pick the file
that matches your device:

| File | Take it if |
|---|---|
| `andee-0.5.3-debug-arm64-v8a.apk` | anything bought in the last several years — **this is the one for almost everyone** |
| `andee-0.5.3-debug-armeabi-v7a.apk` | an older 32-bit device |
| `andee-0.5.3-debug-x86_64.apk` | an emulator |

### This build is deliberately bare

It is built from source with nothing configured — **verified against the generated `BuildConfig`, not
assumed**:

- `CODEFLYING_ENABLED` is `false`, and both `CODEFLYING_KEY` and `CODEFLYING_DOMAIN` are empty, so
  **CodeFlying is not available in this build** and nothing is pre-wired to a hosted backend.
- **The Google voice settings are empty too**, so this build comes up on **Volcengine** and has no
  provider key of any kind baked in.
- `DEFAULT_LANG` is `en`: a device that has never picked a language comes up in **English**.
- The thinking default is off.

### The two keys you have to supply yourself

**The assistant cannot do anything until you give it two keys.** Open **⚙ → Backend → On-device** and
fill in:

1. **The model key (LLM)** — an OpenAI-compatible endpoint plus a model name. On an English UI these
   default to `https://api.openai.com/v1` and `gpt-4o-mini`; a Chinese UI defaults to
   `https://api.deepseek.com` and `deepseek-flash`.
2. **The voice key** — speech recognition and synthesis. Pick the provider first (**Voice provider** →
   Volcengine or Google), then fill in that provider's key: a Volcengine Speech key, or a Google Vertex
   Express key plus a GCP project *number* and a location. Optional: without it the assistant is silent
   but still works on screen — **including the voice exit**, which is matched from recognized speech
   and does not need the model.

Then, in this order: grant **Overlay** → enable **Accessibility** → tap the ball. Until the keys are
in, the card the assistant puts up will name what is missing — that is the self-check working, not a
fault.

> **Would you rather not configure keys at all?** Then this APK is the wrong door. Use the one-click
> page instead — **[codeflying.app/andee](https://www.codeflying.app/andee)**, or
> **[codeflying.net/andee](https://www.codeflying.net/andee)** in mainland China. Describe what you
> want, tap the build button, and you get a package with the **tokens already configured** plus a QR
> code to scan. Starting is free and the free token allowance is **finite — once it runs out, tokens
> must be bought.** It is a separate service with no direct relationship to this project, with its own
> terms, pricing and data handling.

### Why a debug build, when the README says not to hand one out

Because the alternative, today, is no binary at all. The README's advice still stands for anything you
*distribute*: a debug APK is `debuggable`, and its certificate is the **shared Android debug key** —
so it cannot install over a release-signed build, which means moving from this to a signed release
takes an uninstall, and an uninstall takes the notebook and the vault with it. Use this to try the
thing, not to hand it to someone who will depend on it.

## Known issues

- **There is no visible control for the voice exit, and no way to change its phrases.** The list is
  compiled in, and editing it means rebuilding. It is also **English and Chinese only** — a device set
  to another language has no exit phrase it recognizes.
- **The exit phrase must be the whole utterance.** "Okay, exit Andee please" does not match. That is
  the deliberate trade (a substring match would fire on "why did you exit Andee"), but it means the
  feature is easy to fail at by accident, and a failed attempt gives no feedback that it was close.
- **The zoom-then-aim rule is deliberately blunt, and it expires rather than persisting.** On an app
  that hides its tree, *every* plain grid-cell tap is refused, including one aimed somewhere legitimate
  — the model has to zoom first. The rule lifts after two minutes, and clears as soon as the box goes
  away.
- **`fling=true` still coasts unpredictably.** The option exists for long jumps, and its text says so,
  but nothing verifies where the list stopped.
- **The wake threshold's margin is thin**, carried from `v0.3.2` and unchanged here: the eight measured
  judgements sit in 1.47–2.05 with the line landing in the gap between 1.69 and 1.77 — 0.08 wide. There
  is still no quality gate on enrolment takes.
- **A light generated page still fades in over a dark stage.** `TextPage`, `TracePage`,
  `Theme.Body.Fullscreen`'s window background and `HtmlActivity`'s WebView backdrop are all still dark.
  Carried over from `v0.3.1`; the app's own default has been light since `v0.4.1`.
- **A build with CodeFlying compiled in but no API key can still raise the wrong complaint.** The
  availability test looks at `CODEFLYING_ENABLED` and the domain rather than the key. Carried from
  `v0.1.1` onward; not fixed by this release.
- **`assets/andee_key.txt` is tracked by git and is not in `.gitignore`.** It ships empty, which is
  correct — the per-user token is written in at package time. But a local build that fills it in would
  be a key in a tracked file, and nothing currently stops that being committed.
- **`.gitignore` ignores `/build` only, not `build/` at any depth.** A checkout with extra Gradle
  modules writes their build outputs into `<module>/build/`, which is **not** ignored — two such
  directories holding ~258 MB were present during this release. They were never committed and are not
  part of it, but the rule is worth widening before someone adds a module and stages the result by
  reflex.
- The two issues `v0.1.0` listed are **unchanged and untouched in this release**:
  `tools/verify_faces_lab.py` still reports 7/16 assertions passing against the committed
  `reports/ball-faces-lab.html`, and the debug WebSocket server (`net/BodyWsServer`) still binds
  `0.0.0.0:9008` with no authentication (documented in `SECURITY.md`).

## Before you install

Read **[DISCLAIMER.md](../../DISCLAIMER.md)** and
**[docs/acceptable-use.md](../acceptable-use.md)** first. This app asks for accessibility, overlay,
notification access, SMS and call log, and it can complete a payment by tapping. The only guardrail on
that path is Android's `FLAG_SECURE`; the prompt-level checks on risky actions are instructions to the
model, not enforcement.

## Install from source

If you would rather build it yourself — or need a *signed* release build, which is what you should
actually distribute:

```bash
git clone https://github.com/kuafuai/andee
cd andee
git checkout v0.5.3
./gradlew :app:assembleDebug      # installs as-is, signed with the debug certificate
```

To reproduce the attached build exactly, leave `local.properties` with no `CODEFLYING_*` keys, no
`GOOGLE_VOICE_*` keys, and `DEFAULT_LANG=en`; that is the whole configuration, and nothing is passed
on the command line.

`assembleRelease` needs your own keystore — the repo has none, so it produces an unsigned APK that
will not install until you sign it. Full from-scratch setup, including the JDK traps, is in the
README's **Provisioning** section.

**Upgrading from v0.5.2:** `versionCode` moves `11 → 12`, so this installs over it normally. Nothing
you configured is discarded and there is nothing to migrate — the voice exit is compiled in, not
configured. The aiming changes alter what the model does, not what the device stores.
